Introduction

The goal of this analysis is to predict whether a water sample is potable, meaning safe to drink. The response variable is Potability, and the predictors are measurements of water quality such as pH, hardness, solids, sulfate, conductivity, and turbidity.

Two classification methods will be compared:

  1. A classification tree
  2. A random forest

The models will be tuned using five-fold cross-validation and log-loss.

Training and Test Sets

The data is randomly split into a training set containing 70% of the observations and a test set containing the remaining 30%. Stratification helps keep the proportion of potable and non-potable samples similar in both sets.

set.seed(558)

water_split <- initial_split(
  water,
  prop = 0.70,
  strata = Potability
)

water_train <- training(water_split)
water_test <- testing(water_split)

Check the size of each dataset.

The training data will be used to build and tune the models. The test data will only be used for the final comparison.

Cross-Validation

Five-fold cross-validation divides the training data into five sections. Each model is trained on four sections and evaluated on the remaining section. This process is repeated until every section has been used for evaluation.

set.seed(558)

water_folds <- vfold_cv(
  water_train,
  v = 5,
  strata = Potability
)

Log-loss will be used to evaluate the models.

log_loss_metrics <- metric_set(mn_log_loss)

Preprocessing Recipe

Some predictors contain missing values. These values are replaced with the median calculated from the training data. Using a recipe ensures that preprocessing is learned from the appropriate training portion during resampling rather than from the full dataset. :contentReferenceoaicite:1

water_recipe <- recipe(
  Potability ~ .,
  data = water_train
) |>
  step_impute_median(all_numeric_predictors())

All nine water-quality measurements are included as predictors.

Classification Tree

Model Explanation

A classification tree makes predictions by repeatedly dividing the data into smaller groups. Each split is based on a predictor and a cutoff value. For example, the model could first divide samples by sulfate level and then divide each group by pH or hardness.

The final groups are called terminal nodes or leaves. Each leaf produces a predicted class and probability. A tree is easy to understand, but a tree that grows too large may learn random patterns in the training data. This is known as overfitting.

The complexity parameter controls how much the tree is pruned. A smaller value allows a more complicated tree, while a larger value produces a simpler tree. Tidymodels calls this parameter cost_complexity. :contentReferenceoaicite:2

Classification Tree Specification

tree_spec <- decision_tree(
  cost_complexity = tune(),
  tree_depth = 10,
  min_n = 10
) |>
  set_engine("rpart") |>
  set_mode("classification")

Classification Tree Workflow

tree_workflow <- workflow() |>
  add_recipe(water_recipe) |>
  add_model(tree_spec)

Random Forest

Model Explanation

A random forest combines predictions from many classification trees. Each tree is built from a random sample of the training data. At each split, the model also considers only a random subset of predictors.

A single classification tree can change greatly when the training data changes. A random forest reduces this problem by averaging predictions across many different trees. This often improves prediction performance, although the final model is harder to interpret than one classification tree. :contentReferenceoaicite:3

The mtry parameter controls how many predictors are randomly considered at each split. Tuning mtry helps find the value that produces the best predicted probabilities.

Random Forest Specification

rf_spec <- rand_forest(
  mtry = tune(),
  trees = 1000,
  min_n = 5
) |>
  set_engine("ranger") |>
  set_mode("classification")

Random Forest Workflow

rf_workflow <- workflow() |>

Final Model Selection

The best classification tree and best random forest are compared using their log-loss on the test data. The model with the lower test log-loss is selected as the overall winner.

model_comparison <- bind_rows(
  tree_test_results |>
    collect_metrics() |>
    mutate(Model = "Classification Tree"),
  
  rf_test_results |>
    collect_metrics() |>
    mutate(Model = "Random Forest")
) |>
  select(Model, .metric, .estimate) |>
  arrange(.estimate)

model_comparison
# A tibble: 2 × 3
  Model               .metric     .estimate
  <chr>               <chr>           <dbl>
1 Random Forest       mn_log_loss     0.602
2 Classification Tree mn_log_loss     0.669
winning_model <- model_comparison |>
  slice_min(
    order_by = .estimate,
    n = 1,
    with_ties = FALSE
  )

winning_model
# A tibble: 1 × 3
  Model         .metric     .estimate
  <chr>         <chr>           <dbl>
1 Random Forest mn_log_loss     0.602

The Random Forest is the overall winner because it produced the lower test-set log-loss of 0.6021.
